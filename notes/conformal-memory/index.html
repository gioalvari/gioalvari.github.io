Retrieved is not readable: calibrating an agent memory proxy

September 2026 · agent-memory-layer, conformal prediction, LongMemEval

agent-memory-layer is a proxy that stores an agent's past interactions and injects the most relevant ones into each new request. It has one knob that matters more than any other: how many memories to inject. I wanted that number to come with a guarantee instead of a guess, so I calibrated it with conformal prediction. The guarantee held. It just turned out to be about the wrong thing.

The setup

I used LongMemEval-S (cleaned, MIT): 500 questions, each with its own haystack of about 245 past user–assistant pairs, and labels for which turns contain the evidence. 467 questions have labeled evidence; the rest are abstentions. Every pair is embedded with the proxy's model, nomic-embed-text, and scored exactly as the proxy scores it: the maximum cosine similarity of the query against the user and the assistant side. All numbers are averaged over 200 random 50:50 calibration/test splits with a fixed seed.

First, the ranking was wrong

The proxy multiplied similarity by a recency decay that falls to 0.5 after 30 days. On this benchmark, that cost ten points: an evidence memory was in the top 5 for 75.2% of questions, against 85.6% with raw similarity. The damage was concentrated on knowledge updates (65% → 96%). Those are questions where the user once said something, then corrected it, and the old turn is still relevant. Temporal-reasoning questions lost about one point. The proxy now ranks by similarity and uses recency only to break near-ties.

Conformal k

For each calibration question, take the rank of its best evidence memory. That rank is the nonconformity score: the number of memories you would have needed. The split-conformal quantile, the ⌈(1 − α)(n + 1)⌉-th smallest rank, gives a k such that a new, exchangeable question has evidence in its top k with probability at least 1 − α. On the test folds this held: 82.6%, 90.8% and 95.4% observed coverage for 80, 90 and 95% targets.

The obvious alternative, a threshold on the similarity score, is also valid but wasteful. Scores are not comparable across queries, so a threshold loose enough for hard queries injects dozens of memories into easy ones. At the same 90% target it injected 32% more text than a rank k with raw similarity, and 7× more with the old decayed score.

Then I made a mistake. I shipped --target-coverage 0.8 | 0.9 | 0.95 with k = 4 / 8 / 19: the rounded means of the k values over 200 splits. That describes how much k varies between splits, but it is not a conformal quantile of anything. The shipped constant should be one quantile over all 467 labeled questions, which gives 4 / 8 / 16.

A guarantee the proxy could silently break

The guarantee assumes all k memories reach the model. The proxy also enforces a token budget for the memory block, and it drops the lowest-ranked memories that do not fit. My README warned that eight memories needed about 4,300 tokens, twice the default budget. That number was wrong too. The study counted the full text of each memory, but the proxy injects one line per memory with each side cut to 200 bytes. A line costs about 96 tokens, so eight memories cost 815, not 4,300.

The proxy now derives a worst-case bound for one line and, when a coverage target is set, sizes the budget to fit k lines. With 200-byte lines only the 95% target in legacy mode exceeds the default. An explicit budget is respected, but the proxy logs that it can break the target. When the context-size guard cuts k for a request, that is logged too.

  • Calibrate tokens instead of memories. Since the budget is what actually constrains the proxy, I calibrated the tokens needed to reach the first evidence. It saves 5%. Truncation makes every line almost the same length, so a token budget and a count are nearly the same policy. It would matter with long, variable lines.
  • Adapt k to the query. A marginal guarantee can hide very uneven coverage. Split questions into terciles of their top-1 similarity, which the proxy knows before it injects anything. The global 90% k covers the least confident third only 80% of the time, and the most confident third 99.4% of the time. A separate quantile per tercile (Mondrian conformal) gives 91, 92 and 94%, with about 24, 8 and 4 memories. That costs 45% more tokens, moved from easy queries to hard ones. It is now an opt-in flag, --adaptive-k, calibrated on all 467 questions (about 155 per tercile); below is why it is not the default.
  • Control recall, not "at least one". Questions have 1.9 evidence turns on average, and a 90% coverage target retrieves all of them only 60% of the time. Conformal risk control bounds the expected fraction of missed evidence instead: k = 17 for 90% expected recall. The 80%-recall k is 8, the same as the 90%-coverage k, so the two targets are two readings of the same curve.

Retrieved is not readable

Every number so far counts a question as covered when a memory labeled as evidence is injected. But 99.7% of evidence assistant turns and 82% of evidence user turns are longer than 200 bytes, so the injected line is a prefix. I took the 214 questions whose short answer (up to 40 characters) appears verbatim in an evidence turn and checked whether it is still there after truncation.

The calibrated 90% setting, eight memories of 200 bytes, shows the answer in 57% of these questions. For the same ~800 tokens, two memories of 1,600 bytes show it in 72%. Four memories of 800 bytes beat sixteen of 200 bytes with a third fewer tokens. Once retrieval is decent, line length matters more than depth. This probe only counts whether the answer string survives, so I also checked what a model does with it.

Asking a model

I asked two models, Qwen2.5-7B-Instruct and Llama-3.1-8B-Instruct (both Q4_K_M, local llama-server, greedy decoding), the same 214 questions, with memories formatted exactly as the proxy injects them. A reply counts as correct when the gold answer appears in it as whole words, with no LLM judge. Differences are paired bootstrap intervals over the same questions.

At 200 bytes, more memories do almost nothing: on Qwen, 5, 8 and 16 lines all score about 40%. Doubling the line length gains 13.6 points with five memories on Qwen (95% interval 7.9 to 19.2) and 17.3 on Llama (11.7 to 22.4), for about 270 more prompt tokens. Retrieval is still the ceiling: injecting only the labeled evidence scores 65–66% at the same cost as eight short lines. The proxy default is now 400 bytes, the longest at which the default five memories always fit the 2,048-token budget.

The adaptive k is the humbling row. Overall it is within two points of a fixed eight memories on both models, with an interval that straddles zero, for about a quarter more prompt tokens. Split by tercile, it does what it was designed to do: on queries whose best match is weak it gains 4.5 points on Qwen and 12 on Llama. But on confident queries it drops from eight memories to four and loses 5–6 points. A 95% chance that some evidence is in the top four is not the same as the model having enough context to answer. The terciles hold only 63–84 of these questions each, so this is directional.

The fix is a floor: never go below the global k of eight. Confident queries get their accuracy back, the weak tercile keeps its gain, and the set still contains both conformal sets, so both guarantees hold. Against a fixed eight it gains 1.4 points on Qwen and 3.7 on Llama (95% interval 0.9 to 7.0). It is still not the best use of the tokens: eight memories of 800 bytes cost about the same and score 3.3 and 5.6 points higher. The proxy's --adaptive-k now uses the floor and stays opt-in. This is still two models, one prompt, and questions with short verbatim answers.

What I take from this

  • A conformal guarantee is exactly as good as the event it is about. "Evidence was retrieved" was easy to label and calibrate; "the model could answer" is what I cared about, and a one-line formatting default moved it by 13 points.
  • Spend context on longer memories before more memories. Every way I tried of adding depth, fixed or adaptive, lost to giving the same tokens to fewer, longer lines.
  • Calibrate the thing you ship. An average of split quantiles is a good plot, not a shipped constant.
  • Check every step between the guarantee and the model. A budget, a truncation or a context guard can undo it without an error.
  • The limits are real. Coverage is marginal and assumes deployment queries are exchangeable with LongMemEval. The dataset's session dates are synthetic. The constants hold for one embedding model.
